# 歌曲自动缓存 Implementation Plan

**Goal:** 在线播放时自动保存歌曲，完整缓存后下次直接从本地播放，并可查看和清除缓存。

**Architecture:** 独立的歌曲缓存目录和清单，复用下载文件的完整性检查。播放源用一个完整 HTTP 流持续写入磁盘，解码器从已写入区域读取；超出当前区域的拖动请求仍直接使用百度 Range。只有长度校验成功才加入缓存清单。完整缓存优先于网络，手动下载优先于缓存。默认 1 GB，按最近使用顺序淘汰，活动播放文件受保护。

**Tech Stack:** Flutter / Dart、现有 just_audio StreamAudioSource、BaiduClient、SharedPreferences 和应用私有文件。

1. 扩展 OfflineLibrary 以支持独立清单、包含大小的缓存键、已写入文件登记和最近使用排序。实现 PlaybackCache 的写入票据、串行修改、容量、取消/清除、文件保护和缓存转下载。
2. 新增 CachingAudioSource，复用原始播放数据、磁盘背压和有界读取。网络或磁盘异常不登记残缺文件；磁盘不可用时回退直接播放。切歌/停止取消未完成缓存；清除后旧任务不能重新登记。
3. MusicHandler 按手动下载→缓存→在线播放选择数据源；在播放器展示缓存来源。AppController 将完整缓存合并进本地目录；网盘移动/删除及断开账号处理缓存生命周期。
4. 增加歌曲缓存管理页，查看已缓存数量、占用与 1 GB 上限；确认清除时停止当前播放，保留手动下载。下载同一首时优先复制完整缓存。
5. 自动测试覆盖完整性/重启、缓存命中零网络、容量与最近使用、分段和拖动、流取消和故障、清除竞态、下载隔离及缓存管理交互。实际 APK 检查自动缓存、重启断网播放缓存、清除和下载保留。完成格式、分析、测试后发布 v0.5.0，通过企微发送一次下载通知。

**Validation limits:** 不使用真实百度凭据。网络测试使用模拟音频流，设备检查使用内置原创音频走同一个缓存播放源；真实网盘格式、速度和后台限制仍需用户手机验证。
