# 播放页歌词与搜索稳定性 Implementation Plan

**Goal:** 在播放页左右滑动切换封面和歌词，左上角只提供歌词/封面搜索，改善搜索失败体验。

**Architecture:** 保留直连百度及已有歌曲资料缓存。播放页使用 PageView，共享播放进度与控制；移除独立资料页及手机资料导入入口。在线资料客户端按服务串行排队、独立限流，GET 有限重试并区分网络、服务、限流、缺少封面的错误，搜索结果缓存与重复请求合并。

**Tech Stack:** Flutter PageView、Dart http、LRCLIB、MusicBrainz / Cover Art Archive、现有 audio_service。

## 实施步骤

1. 修改 `lib/data/online_catalog.dart`，按来源隔离请求队列与 Retry-After；请求及读取全程有超时、取消与大小边界。临时网络或 5xx 最多重试一次，长限流显示等待时长。规范文件名带出的歌名/歌手，精确无结果时放宽到关键词及仅歌名。成功结果缓存，防止连点重复请求。
2. 将 `lib/ui/song_details_screen.dart` 拆成歌词组件和搜索页；搜索结果在原页预览/应用，下载封面失败仍保留候选，展示重试，不提前退回播放页；只保留搜索，不提供手机导入。搜索初值清理曲序、扩展名、歌手前缀及音质标记，专辑目录不强制视为歌手。
3. 修改 `lib/ui/player_screen.dart` 为封面/歌词横向分页，标题、进度和控制共用；左上角菜单只有“搜索歌词”“搜索封面”，收起、队列及歌曲管理放右侧。同步切歌和缓存更新，防止为新歌应用旧搜索结果。移除旧资料页入口。
4. 扩充请求重试、服务隔离、搜索放宽、缓存/合并、结果恢复、横向切换及切歌测试。修改 `tools/android_smoke.py`，实际 APK 验证滑动与离线歌词缓存。格式、静态分析及测试通过后推送，GitHub Actions 构建 Android/iOS，检查设备截图并发布 v0.4.0，企微发送一次完成通知。

## 验证边界

本地网络小样本请求成功不能代表用户手机的接口稳定性。保留当前歌词和封面直到新选择成功；无法保证第三方服务永远可达或所有中文歌曲都匹配。不会使用不明代理、共享凭据或自动扫描网盘。
